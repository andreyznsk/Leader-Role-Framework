# Скилл: incident-playbook

## Когда использовать

Для создания Emergency Runbook — на основе разговора с предыдущим Tech Lead или из истории инцидентов.

---

## Промпт

Мне нужен Emergency Playbook. Задай мне следующие вопросы (по одному, не все сразу):

1. Что обычно ломается в проде? (попроси описать топ-3 сценария)
2. Кого нужно уведомить ПЕРВЫМ при инциденте? (имена, контакты)
3. Какие дашборды смотреть в первую очередь?
4. Как выполняется rollback?
5. Где escalation path?

---

После сбора информации создай документ:

```markdown
# Emergency Playbook — [команда] — [дата]

> ⚡ Читай этот документ ТОЛЬКО когда что-то горит в проде

---

## 🚨 PROD DOWN — первые 5 минут

### Шаг 1. Уведомить (немедленно)
| Кто | Контакт | Когда звонить |
|-----|---------|---------------|
| [Имя] | @telegram / телефон | Всегда |
| [Имя] | ... | Если не отвечает первый |

### Шаг 2. Проверить (параллельно)
- [ ] Дашборд: [ссылка] — метрики сервисов
- [ ] Grafana: [ссылка] — error rate, latency
- [ ] Kibana/ELK: [ссылка] — ошибки в логах
- [ ] Kubernetes: `kubectl get pods -n [namespace]`

### Шаг 3. Определить масштаб
- Один сервис или несколько?
- Один регион или все?
- Началось после деплоя?

---

## 🔄 Rollback

```bash
# Откатить последний деплой
# [конкретная команда для вашего CI/CD]
```

**Время rollback:** ~X минут
**Кто принимает решение:** [роль/имя]

---

## 🏥 Частые инциденты

### Инцидент 1: [Название]
**Симптомы:** ...
**Причина:** ...
**Решение:** ...

### Инцидент 2: [Название]
...

---

## 📈 Критические метрики

| Метрика | Норма | Алерт | Критично |
|---------|-------|-------|---------|
| Error rate | < 0.1% | > 1% | > 5% |
| p99 latency | < 500ms | > 2s | > 5s |

---

## 📞 Escalation Path

1. Tech Lead (ты)
2. [Следующий уровень]
3. [Архитектор / CTO]

---

## ✅ После инцидента

- [ ] Postmortem в течение 24 часов
- [ ] Jira тикет с root cause
- [ ] Action items с владельцами
```
