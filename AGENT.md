## LeaderOS Core

**JavaMemoryService** является единой точкой входа для AI-агентов.

- Внешние агенты **не должны** обращаться напрямую к JavaRagService.
- Все запросы к знаниям, задачам, рискам и контексту идут через Memory MCP.
- JavaRagService — внутренний knowledge backend, скрытый за Memory MCP.

**Основные инструменты:**

| Инструмент | Назначение |
|------------|-----------|
| `getContext` | Полный контекст текущей сессии |
| `getTasks` | Задачи на дату |
| `getRisks` | Операционные риски |
| `getPeople` | Данные о людях и стейкхолдерах |
| `searchKnowledge` | Поиск знаний по всей базе |

## Knowledge Search

**Основной инструмент:** `searchKnowledge`

Используй `searchKnowledge` как первый шаг при любом вопросе, требующем знаний из базы.

**Flow:**
```
Agent → Memory MCP → /api/knowledge/search → JavaRagService + Operational Context → Ответ
```

**Когда использовать:**
- Вопросы об архитектуре, процессах, решениях команды
- Поиск релевантных инцидентов и постмортемов
- Контекст по людям, рискам, задачам
- Любой вопрос, где нужна история или документация

## Agent Workflow

```
1. Получить вопрос от пользователя
2. Получить контекст → getContext
3. Искать знания → searchKnowledge
4. Сформировать ответ с учётом контекста и знаний
5. Предложить следующее действие (задача, риск, заметка)
```

## Capture Bot

### Когда использовать

Если пользователь говорит одно из:
- "заметка", "запомни", "зафиксируй", "capture"
- "после встречи", "по звонку", "идея", "риск"
- любая фраза с намерением сохранить наблюдение

→ **Немедленно сохрани**, не задавай уточняющих вопросов.

### Как сохранять

**Основной путь — через API (предпочтительно):**

```bash
curl -s -X POST http://localhost:8082/api/capture \
  -H "Content-Type: application/json" \
  -d '{"text": "<текст>", "source": "agent"}'
```

**Fallback — только файл (если memory-service недоступен):**

Создай файл `capture-inbox/YYYY-MM-DD/HH-MM-SS.md`:

```
---
date: YYYY-MM-DD HH:MM:SS
source: agent
---
<текст пользователя дословно>
```

Файл в `capture-inbox/` создай в любом случае — как резервную копию.

### Правила

- **Не классифицируй** — сохрани raw текст как есть
- **Не интерпретируй** — даже если кажется что это задача или риск
- **Не спрашивай** куда класть — это решит агент вечером
- Подтверди коротко: `✓ Записал в capture-inbox`

### Примеры

| Пользователь пишет | Агент делает |
|--------------------|--------------|
| "заметка: Иван не знает rollback" | сохраняет файл, отвечает "✓ Записал" |
| "после встречи: решили не трогать монолит до Q3" | сохраняет файл, отвечает "✓ Записал" |
| "риск: только один человек знает деплой" | сохраняет файл, отвечает "✓ Записал" |
| "запомни: Петров хочет перейти в другую команду" | сохраняет файл, отвечает "✓ Записал" |

## Workspace структура

Workspace — рабочая область и артефакты.
**Memory Service — источник истины** для оперативных данных.

```
workspace/
├── 00_people/        # Stakeholder Map, заметки о людях
├── 01_services/
│   └── architecture/ # C4, ADR, схемы, карточки сервисов
├── 02_incidents/     # История инцидентов, постмортемы
├── 03_processes/     # Release flow, процессы команды
├── 04_releases/      # Release Notes, чеклисты
├── 05_questions/     # Открытые вопросы
├── 06_decisions/     # ADR
├── 07_risks/         # Operational risks
├── 08_daily_journal/ # Дневник: YYYY-MM-DD-ToDay.md
│   # Утром — план на день. Вечером — отчёт + перенос незавершённого в следующий день.
├── 09_toDo/          # Задачи и бэклог
├── 10_plans/         # Планы и стратегия
├── 11_architecture/  # наши сервисы 
├── 12_prompt/  # полезные промпты 
├── 13_Documentation/  # различная полезная документация 
├── 14_sprints/  # наши спринты 
└── ...
```
