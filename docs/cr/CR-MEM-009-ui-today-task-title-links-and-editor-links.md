# CR-MEM-009: UI Today — clickable task title and links inside editor

**Дата:** 2026-06-24  
**Статус:** Draft  
**Сервис:** MEM / JavaMemoryService  
**Тип:** feature / UX improvement  
**Зона:** `/ui/today`  

## Проблема / Мотивация

Сейчас в `/ui/today` окно редактирования задачи открывается только через иконку карандаша. Это неудобно: пользователь естественно ожидает, что название задачи можно нажать и провалиться в детали.

Также в редакторе задачи ссылки отображаются как обычный текст или недоступны для клика. Если в описании задачи есть URL на Jira, Confluence, GitHub, документацию или письмо, пользователь должен иметь возможность открыть ссылку прямо из редактора.

Цель изменения — сделать `/ui/today` удобнее как рабочий план дня: меньше точечных кликов по маленьким иконкам, быстрее переход в задачу и связанные источники.

## Решение

### 1. Кликабельное название задачи

На странице `/ui/today` название задачи должно стать кликабельной зоной, которая открывает то же окно редактирования, что и кнопка с карандашом.

Требования:

- при наведении мыши на название задачи показывать визуальный признак кликабельности;
- курсор должен быть `pointer`;
- название задачи должно иметь hover-стиль: подчёркивание, акцентный цвет или другой уже принятый UI-паттерн проекта;
- клик по названию должен открывать существующее окно редактирования задачи;
- кнопка-карандаш должна остаться, чтобы не ломать текущий UX;
- поведение должно работать для задач всех статусов, которые отображаются на `/ui/today`: `PENDING`, `TODO`, `IN_PROGRESS`, `DONE`, если они есть на странице;
- если задача отображается в pending-секции, клик по названию должен открывать редактор так же, как действие `[Изменить]`.

### 2. Ссылки внутри редактора задачи

Если в описании задачи есть ссылки, они должны быть доступны для открытия прямо из редактора.

Требования:

- URL вида `http://...` и `https://...` должны автоматически распознаваться как ссылки;
- ссылки должны быть кликабельными;
- ссылки должны открываться в новой вкладке через `target="_blank"`;
- для безопасности добавить `rel="noopener noreferrer"`;
- пользователь не должен терять возможность редактировать текст ссылки;
- если редактор реализован через `textarea`, рядом или ниже должен быть preview-блок с кликабельными ссылками;
- если редактор реализован через contenteditable/HTML-preview, ссылки должны быть кликабельны без XSS-рисков;
- не выполнять произвольный HTML из описания задачи;
- поддержать несколько ссылок в одном описании;
- поддержать ссылки с query-параметрами, якорями и дефисами в пути.

Рекомендуемый UX-вариант:

```text
[textarea: редактируемое описание]

Ссылки из описания:
- https://jira.example/browse/ABC-123
- https://confluence.example/display/TEAM/Page
```

Такой вариант безопаснее, чем рендерить HTML прямо внутри editable-поля.

## Acceptance Criteria

### AC1. Открытие редактора по названию задачи

- GIVEN пользователь находится на `/ui/today`
- AND на странице есть задача
- WHEN пользователь наводит мышь на название задачи
- THEN название выглядит кликабельным
- AND курсор становится `pointer`.

- WHEN пользователь кликает по названию задачи
- THEN открывается то же окно редактирования, что и по кнопке-карандашу.

### AC2. Кнопка-карандаш продолжает работать

- GIVEN пользователь находится на `/ui/today`
- WHEN пользователь нажимает на карандаш задачи
- THEN окно редактирования открывается как раньше.

### AC3. Ссылки в описании доступны из редактора

- GIVEN у задачи в описании есть `https://jira.example/browse/ABC-123`
- WHEN пользователь открывает редактор задачи
- THEN ссылка отображается как кликабельная ссылка в редакторе или preview-блоке
- AND ссылка открывается в новой вкладке.

### AC4. Несколько ссылок

- GIVEN у задачи в описании есть несколько URL
- WHEN пользователь открывает редактор
- THEN все URL отображаются кликабельными.

### AC5. Безопасность

- GIVEN описание содержит текст `<script>alert(1)</script>`
- WHEN пользователь открывает редактор
- THEN скрипт не выполняется
- AND HTML отображается как текст или безопасно экранируется.

## Как тестировать вручную

1. Запустить инфраструктуру:

```bash
docker compose up -d
./test-runner/build.sh
./test-runner/start-services.sh --profile local
./test-runner/healthcheck.sh
```

2. Создать тестовую задачу с ссылками:

```bash
curl -s -X POST http://localhost:8082/api/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Проверить кликабельное название",
    "description": "Ссылки: https://jira.example/browse/ABC-123 и https://confluence.example/display/TEAM/Page?mode=edit#section",
    "priority": "HIGH"
  }'
```

3. Открыть:

```text
http://localhost:8082/ui/today
```

4. Проверить:

- название задачи подсвечивается при hover;
- клик по названию открывает редактор;
- карандаш всё ещё открывает редактор;
- обе ссылки доступны из редактора;
- ссылки открываются в новой вкладке;
- описание можно редактировать и сохранить.

## Зависимости

Нет межсервисных зависимостей.

## Риски

- Если ссылки рендерить как raw HTML внутри редактора, можно создать XSS-риск.
- Если сделать название задачи кнопкой без правильной семантики, может ухудшиться доступность.
- Если повесить обработчик клика на всю строку, можно конфликтовать с checkbox/status/action buttons.

## Рекомендации по реализации

1. Не делать всю строку задачи кликабельной на первом шаге. Сделать кликабельным именно title.
2. Добавить отдельный CSS-класс для title, чтобы E2E мог проверять контракт.
3. Для ссылок использовать безопасный linkify:
   - либо простая JS-функция, которая ищет URL в plain text и создаёт DOM-элементы через `document.createElement('a')`;
   - либо серверный парсер с HTML escaping;
   - не использовать `innerHTML` с пользовательским текстом без sanitizer.
4. Preview ссылок обновлять при открытии редактора и при изменении textarea.
