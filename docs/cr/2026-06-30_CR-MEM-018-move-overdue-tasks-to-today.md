# 2026-06-30_CR-MEM-015: Today UI overdue actions and inline date change

**Дата:** 2026-06-30  
**Статус:** Draft  
**Сервис:** MEM / JavaMemoryService  
**Тип:** Enhancement / UI  
**Branch:** feature/mailAg-001

## Проблема / Мотивация

На странице `/ui/today` пользователь видит задачи текущего дня и управляет ежедневным планом.

Сейчас просроченные задачи с дедлайном раньше сегодняшней даты остаются на старых датах. Пользователю приходится вручную переносить каждую такую задачу на сегодня, чтобы восстановить актуальный план дня.

Также дата задачи в списке Today сейчас отображается как текст. Если пользователь хочет быстро перенести одну конкретную задачу на другую дату, ему приходится открывать отдельный edit-flow или пользоваться отдельными кнопками. Это лишнее действие для ежедневного планирования.

Нужны две связанные UI-доработки:

1. Batch-операция: перенести все просроченные незавершённые задачи на сегодня одной кнопкой.
2. Inline-операция: сделать дату каждой задачи кликабельной, чтобы при клике открыть календарь, выбрать новую дату и сразу сохранить её в задаче.

## Решение

### 1. Batch-кнопка для просроченных задач

Добавить на правую панель страницы `/ui/today` кнопку под кнопкой `Добавить новую задачу`:

```text
Перенести просроченные на сегодня
```

Поведение кнопки:

1. Находит все задачи, у которых deadline/dueDate меньше сегодняшней даты.
2. Переносит такие задачи на сегодняшнюю дату.
3. Переносит только активные незавершённые задачи.
4. Не трогает задачи в статусах `DONE`, `ARCHIVED` и legacy `DELETED`.
5. После выполнения обновляет Today UI, чтобы перенесённые задачи сразу появились в списке текущих задач.
6. Показывает пользователю результат операции: сколько задач перенесено.

### 2. Кликабельная дата задачи с календарём

Сделать дату каждой задачи в списке `/ui/today` кликабельной.

Текущее отображение примерно:

```text
DL 01.07.2026
```

Новое поведение:

1. При наведении дата визуально выглядит кликабельной.
2. При клике по дате открывается date picker / календарь.
3. Пользователь выбирает новую дату.
4. Новая дата сразу сохраняется в задаче.
5. После успешного сохранения строка задачи обновляется без полного ручного edit-flow.
6. Если задача после выбора даты больше не относится к текущему дню, она должна исчезнуть из текущего Today list после refresh/re-render.

## Рекомендуемая бизнес-логика

### Batch-перенос просроченных задач

Критерии выбора задач:

```text
dueDate < today
AND status IN (PENDING, TODO, IN_PROGRESS, BLOCKED if supported)
AND status NOT IN (DONE, ARCHIVED, DELETED)
```

Целевое изменение:

```text
task.date = today
task.dueDate = today
```

Если в текущей модели есть различие между `date` и `dueDate`, рекомендуется:

- `date` — день отображения в Today UI;
- `dueDate` — дедлайн задачи;
- для batch-операции обновлять оба поля на today, чтобы задача больше не считалась просроченной и была видна в сегодняшнем плане.

### Inline-изменение даты одной задачи

При выборе даты через календарь обновлять дату задачи:

```text
task.date = selectedDate
task.dueDate = selectedDate
```

Если в текущей модели `date` и `dueDate` имеют разный смысл, для MVP обновлять оба поля одинаково, чтобы UI Today и дедлайн оставались синхронизированы.

## Изменения в API

### Batch endpoint

Добавить endpoint в `JavaMemoryService`:

```http
POST /api/tasks/move-overdue-to-today
```

Ответ:

```json
{
  "moved": 3,
  "today": "2026-06-30"
}
```

Ошибки:

- `200 OK` — операция выполнена, даже если `moved = 0`;
- `500` — внутренняя ошибка batch update.

### Single task date update endpoint

Добавить endpoint для быстрого изменения даты одной задачи:

```http
PATCH /api/tasks/{id}/date
Content-Type: application/json
```

Request body:

```json
{
  "date": "2026-07-01"
}
```

Response body:

```json
{
  "id": 123,
  "date": "2026-07-01",
  "dueDate": "2026-07-01"
}
```

Если в проекте уже есть endpoint для move task / update task date, использовать его и не дублировать API. В таком случае UI должен вызывать существующий endpoint.

## Изменения в схеме БД

Не требуются.

Операции должны использовать существующую таблицу задач и существующие поля даты/дедлайна.

## UX требования

### Batch-кнопка

1. Кнопка размещается в правой панели под кнопкой `Добавить новую задачу`.
2. Текст кнопки: `Перенести просроченные на сегодня`.
3. Перед выполнением желательно показывать confirm dialog:

```text
Перенести все просроченные незавершённые задачи на сегодня?
```

4. После успешного выполнения показать toast/alert:

```text
Перенесено задач: N
```

5. Если задач для переноса нет, показать:

```text
Просроченных задач нет
```

6. После операции страница `/ui/today` должна обновить список задач.

### Кликабельная дата задачи

1. Дата задачи в строке Today должна быть кликабельной.
2. При hover дата должна подсвечиваться или получать underline/курсор pointer.
3. При клике открывается календарь/date picker.
4. После выбора даты значение сохраняется сразу.
5. На время сохранения желательно показать pending state на дате или заблокировать повторный клик.
6. При успехе показать короткое сообщение:

```text
Дата задачи обновлена
```

7. При ошибке показать понятное сообщение и вернуть старую дату:

```text
Не удалось обновить дату задачи
```

## Acceptance Criteria

### Batch-перенос просроченных задач

- [ ] На `/ui/today` под кнопкой `Добавить новую задачу` есть кнопка `Перенести просроченные на сегодня`.
- [ ] По нажатию кнопки вызывается batch-операция переноса просроченных задач.
- [ ] Переносятся только задачи с `dueDate < today`.
- [ ] Переносятся только незавершённые активные задачи.
- [ ] `DONE`, `ARCHIVED` и legacy `DELETED` задачи не переносятся.
- [ ] У перенесённых задач обновляется дата отображения на сегодня.
- [ ] Если используется отдельный deadline/dueDate, он тоже обновляется на сегодня.
- [ ] После переноса задачи видны в списке Today.
- [ ] UI показывает количество перенесённых задач.
- [ ] Если переносить нечего, UI показывает понятное сообщение.

### Inline-изменение даты задачи

- [ ] Дата каждой задачи на `/ui/today` кликабельна.
- [ ] При клике по дате открывается календарь/date picker.
- [ ] Пользователь может выбрать новую дату.
- [ ] Новая дата сохраняется в задаче без открытия полного редактора задачи.
- [ ] После успешного сохранения дата в UI обновляется.
- [ ] Если новая дата не равна текущей дате Today list, задача исчезает из текущего списка после обновления/перерендера.
- [ ] При ошибке сохранения UI показывает понятное сообщение.
- [ ] `DONE`, `ARCHIVED`, `DELETED` задачи не получают особого скрытого поведения: если они отображаются в UI, дата меняется по тем же правилам, если бизнес-логика сервиса разрешает редактирование.

## Как тестировать

### Manual: batch-перенос

1. Запустить инфраструктуру и `JavaMemoryService`:

```bash
docker compose up -d
SPRING_PROFILES_ACTIVE=local java -jar JavaMemoryService/target/memory-service.jar
```

2. Создать тестовые задачи:

- `TODO` с `dueDate = today - 1 day`;
- `IN_PROGRESS` с `dueDate = today - 2 days`;
- `DONE` с `dueDate = today - 3 days`;
- `ARCHIVED` или legacy `DELETED` с `dueDate = today - 4 days`;
- `TODO` с `dueDate = today`.

3. Открыть:

```text
http://localhost:8082/ui/today
```

4. Нажать кнопку:

```text
Перенести просроченные на сегодня
```

5. Проверить:

- перенесены только `TODO` и `IN_PROGRESS` просроченные задачи;
- `DONE`, `ARCHIVED`, `DELETED` не изменились;
- задачи появились в Today;
- UI показал корректное количество перенесённых задач.

### Manual: кликабельная дата

1. Открыть `/ui/today`.
2. Найти любую активную задачу.
3. Кликнуть по её дате `DL dd.MM.yyyy`.
4. В открывшемся календаре выбрать другую дату.
5. Проверить:

- дата сохранилась;
- при повторном открытии страницы у задачи новая дата;
- если дата выбрана не сегодняшняя, задача больше не отображается в сегодняшнем списке;
- при открытии выбранной даты в календаре/фильтре задача видна там.

### E2E

Добавить сценарии:

```text
JavaMemoryService/test_e2e/15_move_overdue_tasks_to_today.md
JavaMemoryService/test_e2e/16_today_inline_task_date_change.md
```

Сценарий batch-переноса должен:

1. Создать несколько задач с прошедшими датами и разными статусами.
2. Вызвать `POST /api/tasks/move-overdue-to-today`.
3. Проверить `moved` в ответе.
4. Проверить через `GET /api/tasks?date=<today>`, что активные просроченные задачи появились сегодня.
5. Проверить, что `DONE`, `ARCHIVED`, `DELETED` не были перенесены.
6. Проверить smoke `/ui/today`, что кнопка присутствует в HTML.

Сценарий inline-date должен:

1. Создать задачу на сегодня.
2. Вызвать `PATCH /api/tasks/{id}/date` с новой датой.
3. Проверить, что задача исчезла из `GET /api/tasks?date=<today>`.
4. Проверить, что задача появилась в `GET /api/tasks?date=<newDate>`.
5. Проверить smoke `/ui/today`, что дата задачи рендерится как кликабельный элемент / date-control.
