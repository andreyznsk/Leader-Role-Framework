# 2026-06-29_CR-MEM-014: Today UI hide Done tasks filter

**Дата:** 2026-06-29  
**Статус:** Superseded by [CR-MEM-025](2026-07-02_CR-MEM-025-today-todo-done-tabs.md) (2026-07-02) — toggle «No Done» убран, вместо него отдельные вкладки ToDo/Done в сайдбаре.

**Тип:** Enhancement / UI  
**Branch:** feature/mailAg-001

## Проблема / Мотивация

На странице `/ui/today` пользователь фильтрует задачи по статусам и приоритетам, чтобы быстро увидеть актуальную работу на день.

Сейчас при фильтрации задачи со статусом `DONE` могут подниматься наверх и смешиваться с актуальными задачами (`TODO`, `IN_PROGRESS`, `PENDING`). Это создаёт визуальный шум: завершённые задачи не всегда нужны в рабочем фокусе, но иногда их всё же нужно быстро посмотреть.

Нужно дать пользователю простой способ скрывать `DONE` задачи, не удаляя их из данных и не ломая существующие фильтры.

## Решение

Добавить на страницу `/ui/today` UI-переключатель:

```text
[✓] Скрывать Done
```

Поведение:

1. По умолчанию переключатель включён.
2. При включённом переключателе задачи со статусом `DONE` не отображаются в списке Today.
3. При отключённом переключателе задачи со статусом `DONE` отображаются вместе с остальными задачами.
4. Существующие фильтры по статусу и приоритету продолжают работать.
5. Если пользователь явно выбирает фильтр статуса `DONE`, задачи `DONE` должны быть видны, даже если режим hide done был включён ранее.

Рекомендуемая логика:

```text
visibleTasks = tasks
  .filter(bySelectedDate)
  .filter(byPriorityFilter)
  .filter(byStatusFilter)
  .filter(task -> !hideDone || explicitStatusFilter == DONE || task.status != DONE)
```

## Изменения в API

Изменения публичного REST API не требуются.

Доработка может быть реализована полностью на уровне server-side модели `/ui/today` и/или client-side фильтрации в шаблоне Today UI.

Если текущая реализация Today UI уже использует query params для фильтров, добавить параметр:

```http
GET /ui/today?hideDone=true|false
```

Рекомендуемое значение по умолчанию:

```text
hideDone=true
```

## Изменения в схеме БД

Не требуются.

## Зависимости

- `JavaMemoryService`
- Today UI: `/ui/today`
- существующая модель статусов задач: `PENDING`, `TODO`, `IN_PROGRESS`, `DONE`, `DELETED`
- существующие фильтры по статусу и приоритету

## UX требования

1. Переключатель должен быть рядом с существующими фильтрами Today UI.
2. Текст переключателя: `Скрывать Done` или `Hide Done`, в зависимости от языка текущей страницы.
3. Состояние переключателя должно быть понятно визуально.
4. Если выбран статус `DONE`, UI не должен вводить пользователя в заблуждение: `DONE` задачи должны отображаться.
5. После сброса фильтров режим по умолчанию снова скрывает `DONE`.

## Как тестировать

### Manual

1. Запустить инфраструктуру и `JavaMemoryService`:

```bash
docker compose up -d
SPRING_PROFILES_ACTIVE=local java -jar JavaMemoryService/target/memory-service.jar
```

2. Создать несколько задач на сегодня:

- `TODO` с `HIGH`
- `IN_PROGRESS` с `MEDIUM`
- `DONE` с `HIGH`
- `DONE` с `LOW`

3. Открыть:

```text
http://localhost:8082/ui/today
```

4. Проверить:

- по умолчанию `DONE` не видны;
- при выключении `Скрывать Done` — `DONE` появляются;
- при фильтрации по `HIGH` и включённом `hideDone` — `DONE HIGH` не видна;
- при явном выборе статуса `DONE` — `DONE` задачи видны;
- при сбросе фильтров — `DONE` снова скрыты.
