# Скилл: risk-scan

## Когда использовать

Для быстрой оценки рисков на основе описания ситуации, без доступа к Jira.

---

## Промпт

Я опишу ситуацию в команде / системе. Помоги оценить операционные риски.

**Алгоритм анализа:**

1. **Найди риски** в следующих категориях:

| Категория | Что искать |
|-----------|------------|
| 🔴 Релизы | Ручные шаги, нет rollback, один ответственный |
| 🟠 Инфраструктура | SPOF, нет мониторинга, устаревший стек |
| 🟡 Команда | Bus factor = 1, знания в головах, нет документации |
| 🔵 Процессы | Нет runbook, хаос в коммуникациях, нет SLA |
| ⚪ Технический долг | Flaky тесты, legacy код, нет покрытия |

2. **Оцени каждый риск:**
   - Вероятность: высокая / средняя / низкая
   - Влияние: критическое / значительное / минимальное
   - Приоритет = Вероятность × Влияние

3. **Для топ-5 рисков** дай конкретную рекомендацию

**Формат вывода:**

```markdown
# Оценка рисков — [дата]

## Top Risks

| # | Риск | Кат. | Вероятность | Влияние | Приоритет |
|---|------|------|-------------|---------|-----------|
| 1 | ... | 🔴 | Высокая | Критическое | P1 |

## Детали

### 🔴 P1: [Название]
**Что может случиться:** ...
**Признаки уже сейчас:** ...
**Рекомендация:** ...
**Быстрая победа:** [что можно сделать за 1 день]

## 💡 Что можно улучшить быстро (quick wins)
1. ...
```

**Сохрани в** `./workspace/07_risks/risk-assessment-[дата].md`
