# Скилл: release-prep

## Когда использовать

При подготовке к релизу — создаёт все необходимые артефакты за один запрос.

---

## Промпт

Мне нужно подготовить артефакты к релизу. Создай следующие документы:

**Входные данные (попроси у меня если не предоставил):**
- Версия / дата релиза
- Список задач (Jira тикеты или описание)
- Затронутые сервисы
- Тип изменений (feature / bugfix / hotfix / migration)

---

### Документ 1: Release Notes

Аудитория: стейкхолдеры, смежные команды
Тон: технический, конкретный

```markdown
# Release Notes — v[X.Y.Z] — [дата]

## Изменения
| Тип | Описание | Jira |
| 🆕 Feature | ... | |
| 🐛 Fix | ... | |
| ⚡ Performance | ... | |
| 🔧 Tech Debt | ... | |

## Затронутые компоненты
## Зависимости (что нужно от других команд)
## Известные ограничения
```

---

### Документ 2: Release Checklist

```markdown
# Release Checklist — [дата]

## Pre-deploy
- [ ] Code review пройден
- [ ] Тесты прошли (unit + integration)
- [ ] Feature flags настроены
- [ ] Конфиги обновлены в [среда]
- [ ] БД миграции проверены на stage
- [ ] Смежники уведомлены

## Deploy
- [ ] Деплой на [среда]
- [ ] Smoke тесты
- [ ] Мониторинг: метрики в норме

## Post-deploy
- [ ] Release Notes опубликованы
- [ ] Jira тикеты закрыты
- [ ] Команда уведомлена
```

---

### Документ 3: Rollback Plan

```markdown
# Rollback Plan — v[X.Y.Z]

## Критерии для rollback
- Error rate > X%
- Latency p99 > Xms
- [Специфичные для сервиса]

## Шаги rollback
1. ...
2. ...

## Время rollback: ~X минут
## Ответственный: [имя]
## Кого уведомить: [список]
```

---

### Документ 4: Smoke Tests

```markdown
# Smoke Tests — v[X.Y.Z]

## Критические пути (проверить первыми)
- [ ] [Основной бизнес-сценарий 1]
- [ ] [Основной бизнес-сценарий 2]

## Мониторинг
- [ ] Дашборд: [ссылка]
- [ ] Alertmanager: нет новых алертов
- [ ] Логи: нет ERROR уровня
```
