Spec now genuinely covers the hideModeSwitch config, closing the gap noted in the previous entry.

`JavaMemoryService/src/main/resources/static/vendor/toastui/toastui-editor-all.min.js` (as of 2026-07-03) is NOT the self-contained "-all" browser bundle it's named as. Its UMD header does `require("prosemirror-commands")`, `require("prosemirror-history")`, etc., and in the plain-`<script>`-tag (browser global) branch it evaluates to `e.toastui.Editor=t(e[void 0],e[void 0],...)` — i.e. it expects those prosemirror packages as separate externally-loaded globals, which are never provided. Result: `TypeError: Cannot read properties of undefined (reading 'PluginKey')` inside the bundle, followed by `toastui.Editor is not a constructor` in `task-edit.html`'s inline script. `window.toastui` exists as an empty object, but `descriptionEditor` is never assigned — the `#toastui-editor` div stays empty/zero-height ("hidden" per Playwright), so `task-toastui-editor.spec.js` fails at the very first `toBeVisible()` assertion.

**Why:** The genuine `toastui-editor-all.js`/`.min.js` distributed by `@toast-ui/editor` bundles prosemirror internally specifically so it works standalone via `<script>` with zero external deps — that's the whole point of the "-all" variant. What's currently vendored is actually the plain `toastui-editor.min.js` (peer-dependency build), just saved under the "-all" filename.

**How to apply:** This blocks the *entire* WYSIWYG feature client-side (task-edit.html's save flow reads `descriptionEditor.getMarkdown()` directly, no fallback), not just the test. Fix is to re-fetch/re-vendor the correct `toastui-editor-all.min.js` from the official `@toast-ui/editor` npm package (`dist/toastui-editor-all.min.js`, and its source-mapped non-min version if needed) — verify by grepping the file for `require("prosemirror` in the UMD header; a correct "-all" bundle should have no such `require(...)` calls for prosemirror packages in that header. Backend (`/api/tasks`, `/api/tasks/{id}/description`, `/export-md`, `/api/search`) was not exercised end-to-end by this failure since the editor never mounted, but curl-level checks (task create, vendor asset 200s) all passed fine — the defect is isolated to this one vendor file.
