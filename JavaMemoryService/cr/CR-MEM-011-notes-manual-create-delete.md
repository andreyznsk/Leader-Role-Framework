# CR-MEM-011: Operational Notes — ручное добавление и удаление заметок

**Дата:** 2026-06-26  
**Статус:** Implemented  
**Тип:** feature  
**Сервис:** JavaMemoryService  
**Экран:** `GET /ui/notes`  
**Связанный URL:** `http://localhost:8090/ui/notes`

---

## Проблема

Текущий экран `Operational Notes` показывает список заметок, фильтр по `tags` и действие
`→ В задачу`, но не покрывает два базовых пользовательских сценария:

1. Нельзя вручную создать заметку прямо из UI.
2. Нельзя удалить заметку из списка.

Из-за этого `/ui/notes` работает только как read-only лента для уже созданных записей и
не подходит для ручного оперативного ведения заметок.

---

## Цель

Сделать `/ui/notes` рабочим CRUD-экраном для operational notes в рамках двух сценариев:

1. пользователь может добавить новую заметку вручную;
2. пользователь может удалить любую заметку прямо из списка.

---

## Текущее состояние

### Уже есть

- `POST /api/notes` — создание заметки;
- `GET /api/notes` — список заметок;
- таблица `notes` уже содержит нужные поля: `text`, `tags`, `source`, `created_at`;
- страница `notes.html` уже рендерит список заметок и использует общий JS helper
  `window.LeaderUiApi`.

### Нет

- `DELETE /api/notes/{id}`;
- UI-формы для ручного добавления заметки;
- UI-кнопки удаления на карточке заметки;
- тестов на create/delete flow для notes UI.

---

## Решение

### 1. Ручное добавление заметки на `/ui/notes`

Добавить на страницу кнопку `+ Добавить заметку`, открывающую Bootstrap modal.

Поля формы:

- `text` — обязательное, `textarea`;
- `tags` — необязательное, `input`;
- `source` — скрытое поле, значение `manual-ui`.

Поведение:

- submit делает `POST /api/notes`;
- при успехе страница перезагружается и новая заметка появляется вверху списка;
- при ошибке показывается inline-сообщение в модалке;
- `tags` нормализуются существующей логикой `NoteService.normalizeTags(...)`.

### 2. Удаление заметки из списка

На каждой карточке заметки добавить кнопку удаления `×` / `Удалить`.

Поведение:

- клик открывает короткое подтверждение удаления;
- подтверждение делает `DELETE /api/notes/{id}`;
- при успехе страница перезагружается;
- удаление физическое (`hard delete`), без статуса soft delete.

Для `notes` soft delete не нужен: сущность не имеет lifecycle-статусов, а сценарий
страницы предполагает именно очистку оперативной ленты.

## Изменения в API

### Новый endpoint

```http
DELETE /api/notes/{id}
```

**Response:**

- `204 No Content` — заметка удалена;
- `404 Not Found` — заметка не существует.

### Используемый существующий endpoint

```http
POST /api/notes
Content-Type: application/json

{
  "text": "Нужно обсудить rollback process с командой",
  "tags": "team,process",
  "source": "manual-ui"
}
```

## UI-спецификация

### Верхняя панель страницы

Справа от фильтра либо рядом с заголовком добавить кнопку:

```text
+ Добавить заметку
```

### Модалка создания

```text
┌─────────────────────────────────────────────────┐
│ Новая заметка                                ✕ │
│                                                 │
│ Текст *                                         │
│ [ textarea                                 ]    │
│                                                 │
│ Tags                                            │
│ [ team,process                            ]     │
│                                                 │
│              [Отмена] [Добавить заметку]        │
└─────────────────────────────────────────────────┘
```

### Карточка заметки

В actions-строке карточки должны быть доступны:

- tags;
- `→ В задачу`;
- `Удалить`.

Кнопка удаления должна быть визуально вторичной по отношению к основному действию
`→ В задачу`, но явно заметной.

---

## Нефункциональные требования

1. Без миграций БД.
2. Без изменений модели `Note`.
3. Не ломать существующий flow `POST /api/notes` от Capture Router.
4. Не менять текущую механику фильтра `tags` и `limit`.
5. Использовать существующий клиентский helper `window.LeaderUiApi`, а не вводить новый JS-слой.

---

## Acceptance Criteria

1. На `http://localhost:8090/ui/notes` есть кнопка `+ Добавить заметку`.
2. Пользователь может создать заметку вручную без перехода на другой экран.
3. Новая заметка после создания появляется в ленте заметок.
4. На каждой заметке есть действие удаления.
5. После подтверждения заметка исчезает из списка и не возвращается при reload.
6. Кнопка `→ В задачу` продолжает работать как раньше.
7. `GET /api/notes` после удаления не возвращает удалённую запись.

---

## Как проверить

### API

```bash
NOTE_ID=$(curl -s -X POST http://localhost:8090/api/notes \
  -H "Content-Type: application/json" \
  -d '{"text":"CR-MEM-011 test note","tags":"ui,test","source":"manual-ui"}' | jq -r '.id')

curl -s http://localhost:8090/api/notes?limit=20 | jq '.[] | select(.id == '"$NOTE_ID"')'

curl -i -X DELETE "http://localhost:8090/api/notes/$NOTE_ID"
# Ожидается: HTTP/1.1 204

curl -s http://localhost:8090/api/notes?limit=20 | jq '.[] | select(.id == '"$NOTE_ID"')'
# Ожидается: пусто
```

### UI

1. Открыть `http://localhost:8090/ui/notes`
2. Нажать `+ Добавить заметку`
3. Ввести текст и при необходимости tags
4. Сохранить
5. Убедиться, что заметка появилась сверху списка
6. Нажать `Удалить` на этой же заметке
7. Подтвердить удаление
8. Убедиться, что заметка исчезла и не возвращается после reload

---

## Риски

1. Если удалить без подтверждения, легко потерять заметку случайным кликом.
2. Если не передавать `source` из UI, новые ручные заметки будут сохраняться как `agent`,
   что создаст неверный источник в UI.
3. Если сделать delete как обычную ссылку без API-flow, поведение будет выбиваться из
   остального UI и усложнит обработку ошибок.

---

## Out of Scope

В этот CR не входят:

- редактирование существующей заметки;
- bulk delete;
- pin/favorite/archive для notes;
- отдельные права доступа на удаление;
- перенос заметки в knowledge / capture / person note.
