# CR-MEM-002: Capture Bot — улучшения планировщика и UI

**Дата:** 2026-06-12
**Статус:** Approved
**Сервис:** MEM (JavaMemoryService)
**Зависимости:** CR-MEM-001 (должен быть реализован первым)

---

## Проблема / Мотивация

CR-MEM-001 заложил базовую механику захвата и классификации. После анализа
поведения выявлены три зоны улучшения:

1. **Жёсткий cron 18:00** — не гибко, нельзя менять без пересборки
2. **Классификация без контекста** — агент не знает текущие задачи и риски,
   создаёт дубли
3. **Нет ручного управления NOTE/RISK** — нельзя превратить заметку в задачу
   без ручного ввода

---

## Решение

### 1. Конфигурируемый cron в properties

```properties
# application.properties
capture.scheduler.cron=0 0 * * * *
# По умолчанию — каждый час. Примеры:
# 0 0 18 * * *   — раз в день в 18:00 (оригинальное поведение)
# 0 0 * * * *    — каждый час
# 0 */30 * * * * — каждые 30 минут
```

`CaptureScheduler`:
```java
@Scheduled(cron = "${capture.scheduler.cron:0 0 * * * *}")
public void processCaptures() { ... }
```

---

### 2. Алгоритм обработки файлов (идемпотентный)

Файлы в `capture-inbox/YYYY-MM-DD/` — очередь необработанных.
Файл перемещается в `processed/` сразу после успешной обработки.

```
1. ls capture-inbox/YYYY-MM-DD/*.md  (сегодня, не из processed/)
2. Если список пуст → выход
3. GET /api/context → текущие задачи + открытые риски
4. Сформировать батч-промпт (все файлы + контекст дня)
5. claude --print "<промпт>"
6. Если JSON невалидный → log.warn, выход (все файлы остаются)
7. Для каждого элемента из JSON:
   a. Выполнить action:
      TASK → POST /api/tasks/pending
      RISK → POST /api/risks
      NOTE → POST /api/notes
   b. Если action успешен → mv файл в capture-inbox/processed/YYYY-MM-DD/
   c. Если action упал   → log.warn, файл остаётся (попадёт в следующий запуск)
```

Если агент вернул JSON без упоминания какого-то файла — файл остаётся
в очереди и попадёт в следующий батч.

---

### 3. Промпт с контекстом дня

```
Классифицируй каждую заметку. Верни ТОЛЬКО JSON массив, без пояснений.

Контекст дня (уже существуют, не дублируй):
Задачи: ["Обсудить архитектуру payments", "Провести 1-1 с Иваном"]
Открытые риски: ["Только один человек знает деплой"]

Типы классификации:
- TASK — действие которое нужно выполнить (не дублируй существующие задачи)
- RISK — операционный риск или проблема (не дублируй существующие риски)
- NOTE — наблюдение, информация к сведению

Заметки:
[{"file": "10-32-00.md", "text": "..."},
 {"file": "14-15-00.md", "text": "..."}]

Формат ответа:
[
  {"file": "10-32-00.md", "type": "TASK", "title": "...", "priority": "HIGH|NORMAL|LOW"},
  {"file": "14-15-00.md", "type": "RISK", "title": "..."},
  {"file": "16-40-00.md", "type": "NOTE", "title": "..."}
]
```

`CaptureScheduler` перед запуском `claude --print` вызывает `contextService.buildContext()`
и вставляет в промпт списки title существующих задач и открытых рисков.

### 4. Кнопка "Перенести в задачу" — Notes и Risks

#### На странице `/ui/notes`

Каждая карточка заметки получает кнопку **[→ В задачу]**.

Клик → модалка Bootstrap:

```
┌─────────────────────────────────────────────────┐
│ Создать задачу из заметки                    ✕  │
│                                                  │
│ Название *                                       │
│ [Иван не знает процедуру rollback          ]    │
│                                                  │
│ Приоритет                                        │
│ ○ LOW  ● NORMAL  ○ HIGH  ○ CRITICAL             │
│                                                  │
│ Срок (необязательно)                             │
│ [          ]  (date picker)                      │
│                                                  │
│           [Отмена]  [Создать задачу]             │
└─────────────────────────────────────────────────┘
```

Предзаполнение: `title` = текст заметки (обрезанный до 200 символов), `priority` = NORMAL.

POST `/api/tasks/pending` → задача появляется в `/ui/today` в секции PENDING.

#### На странице `/ui/risks`

Каждая строка риска получает кнопку **[→ В задачу]**.

Модалка аналогичная, `title` предзаполняется из `risks.title`.

|------|-----------|

## Как тестировать

```bash
# 1. Проверить что cron читается из properties
# application-local.properties:
# capture.scheduler.cron=0 */1 * * * *  ← каждую минуту для теста

# 2. Положить несколько заметок
curl -X POST http://localhost:8082/api/capture \
  -H "Content-Type: application/json" \
  -d '{"text": "Петров уходит в отпуск на 2 недели", "source": "manual"}'

curl -X POST http://localhost:8082/api/capture \
  -H "Content-Type: application/json" \
  -d '{"text": "нужно обновить runbook по деплою", "source": "manual"}'

# 3. Дождаться срабатывания (или process-now)
curl -X POST http://localhost:8082/api/capture/process-now

# 4. Проверить что файлы переехали в processed/
ls Leader-Role-Framework/capture-inbox/processed/$(date +%Y-%m-%d)/

# 5. Проверить кнопку [→ В задачу]
# Открыть /ui/notes, нажать кнопку, заполнить модалку
# Проверить что задача появилась в /ui/today в секции PENDING
```
